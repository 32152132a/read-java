# 发音资源与功能开关

本说明对应 V27/V28 及配套前端。前后端须一起更新；本次不提供旧数据结构的运行时兼容分支。

## 唯一来源

- `words` 保存词条 ID、拼写、释义和 `variant_key`。同形异音或不同词义的词条不能只按拼写强行合并。
- `word_pronunciations` 以 `(word_id, accent)` 唯一保存 IPA 和音频。`accent` 只能是 `US` 或 `GB`。
- `phonemes` 的 `detail_json` 保存说明（含简短拟音）、发音步骤、嘴形、记忆提示与教学题目。符号、分类和分组由对应列维护，不再复制到另一份公共配置。
- `phoneme_pronunciations` 以 `(phoneme_id, accent)` 唯一保存录音。
- `phoneme_examples` 保存 `(phoneme_id, word_id, accent, sort_order)`，各页面例词从对应单词读取最新资料。
- 课程里的单词、对比词、音标与听音题选项引用稳定 ID。课程自己的顺序、拆读、重音与讲解保留。
- 个人单词配置只保存教学内容及个人释义，不允许修改共享发音资源。管理员从公共词条编辑维护英美资源；音频和 IPA 写入资源表，不写回教学 JSON。

接口中的 `ipa`、`audio.url` 和 `audioUrl` 是为当前页面组装的展示结果；它们不是额外的数据源。后端按用户偏好选口音；偏好资源缺失时返回实际可用的另一口音并标明 `accent`。课程或例词明确指定口音时严格使用该口音，缺失则留空，避免把另一口音的单词挂到不相符的音标下。不用 AI 或 ARPAbet 转换补造缺失的另一套 IPA 或音频。

## 接入音频

先确认录音对应的词条或音标、口音、授权和可分发地址。本项目不会因开关开启而自动购买或生成音频。

单词通过公共内容编辑的 `pronunciations.US/GB` 维护；也可在受控数据维护中更新资源表对应的一条记录。示例（仅示意，不在生产直接执行）：

```sql
UPDATE word_pronunciations
SET ipa = '/sɪt/', audio_url = 'https://your-cos-domain/sit-gb.mp3'
WHERE word_id = '实际词条ID' AND accent = 'GB';
```

音标在 `phoneme_pronunciations` 中按口音维护。补齐哪条资源，引用它的详情、课程、例词和词库在下次请求时即获得更新；无需改前端代码。已经打开的页面需重新加载。

## 两个独立开关

`learning_features` 默认有以下两行，均为 `FALSE`：

| code | 作用 |
| --- | --- |
| `phoneme_audio` | 允许显示有实际音频的音标播放按钮，不影响单词朗读 |
| `phoneme_listening` | 允许听音阶段；同时要求前一个开关开启，且全部启用听音题的目标音标已有音频 |

只准备了几个音标时，可以单独打开播放开关，缺音频的音标仍不显示按钮。不要为了开放听音阶段填入错误录音。

`GET /api/v1/content/capabilities` 在登录后返回 `phonemeAudioEnabled` 和有效的 `phonemeListeningEnabled`。前端在全局 Pinia 状态中保存，并发请求共用一次加载；失败默认关闭，下次可重试。配置不持久化到本地缓存，重新启动应用后会重新获取。修改开关无需重启后端，已打开的客户端需重新进入应用。

后端也使用相同数据库开关控制模板、流程与阶段访问。关闭时题目与节点保留，推进流程时绕过听音节点，不将跳过的节点伪记为已完成。已经越过的阶段不会强制用户重新学习；可以通过流程编辑开始新一轮。

## 迁移与验证边界

V27 创建资源、例词关联与开关表。V28 是一次性 Java Flyway 数据迁移：补齐课程引用的词条、保留课程及题目、迁入拆读教学配置、合并中文拟音到音标说明，之后删除基础表旧音频/口音/IPA列及 JSON 中的重复资源字段。

现有基础单词明确标注的口音保留；课程与音标例词的现有英式 IPA 作为 GB 资料迁入，不自动推算另一套 IPA。只有拼写而没有 IPA 的对比词保留引用，缺少的 IPA 和释义需要后续补齐。迁移不会校正所有教学文案或证明录音授权。

课程单元、题目和词库数据不清空；不删除用户账号或远程数据。部署前必须备份实际数据库，并在隔离 MySQL 中验证 V27/V28；MySQL 的 DDL 不能视为整段迁移可事务回滚。不要修改已执行的旧迁移，也不要在旧版后端仍运行时删除字段。
